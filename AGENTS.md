# tasks

> [!WARNING]
> TanStack Start is NOT Next.js. There is no `getServerSideProps`, no
> `"use server"` / `"use client"` directive, no App Router (`app/page.tsx`,
> `layout.tsx`, `route.ts`), no `next/*` import and no React Server Actions.
> Data loads in route `loader`s and server functions (`createServerFn`);
> HTTP endpoints are server routes (`createFileRoute(...)({ server: { handlers } })`).
> If you catch yourself writing a Next.js pattern, load the skills below first.

`tasks` is a Reminders-style tasks PWA over Nextcloud CalDAV, served at
`tasks.viktorbarzin.me`, built on the default app stack in
`~/code/docs/adr/0001-default-app-stack.md`. Domain language is in
[CONTEXT.md](CONTEXT.md); the API contract is in `docs/` and
`src/shared/contract.ts`. Every push to `master` builds and deploys the live
app (`.github/workflows/build.yml`, `.woodpecker/deploy.yml`), so land only
verified work there.

## Conventions

### Server-only code lives in `*.server.ts`

Everything that touches the database, CalDAV, crypto, secrets or Bun's
built-ins lives under `src/server/` in files named `*.server.ts`. Import
those modules only from:

- server route handlers (`src/routes/**`, inside `server.handlers`),
- server function handlers (inside `.handler(...)`),
- other `*.server.ts` modules, `src/start.ts` middleware `.server(...)` bodies,
  and `src/entrypoints/*`.

Never import them from a component, a hook, `src/shared/`, or a plain helper
module that a component imports. Start strips server-function and
server-route bodies from the client bundle, but a plain exported helper that
touches the database, sitting in a module the client imports, drags the
Postgres driver into the browser bundle. `vite build`, `tsc` and `curl` all
pass; only a real browser shows `Buffer is not defined` on hydration and every
button silently stops working. After adding server code, run
`bun run test:e2e` (a real Chromium) before calling it done.

There is no lint guard for this (Viktor declined a mandatory one); keep the
convention by hand.

### Server functions vs server routes

- Server functions (`createServerFn`) are internal RPC for this app's own UI.
  They are served at `/_serverFn/<hash>` and speak seroval, so CLIs, agents and
  Home Assistant cannot call them.
- Anything a non-browser client calls is a server route under `/api` with a
  zod schema. The JSON contract the existing PWA uses is in
  `src/shared/contract.ts` and must stay byte-compatible.
- The validator method in Start 1.169 is `.validator()`, not
  `.inputValidator()` (older docs and model memory use the latter).
- `src/routeTree.gen.ts` is generated by `vite build` / `vite dev` and is
  committed. `tsr generate` writes a different file (no Start `Register`
  config block); do not use it.

### Layout

```
src/
  routes/            file routes; /api/* and /healthz are server routes;
                     UI routes: index (Home), list.$id, view.$view (all ssr: false)
  components/        React screens and pieces, tasks.css (the iOS look), shadcn/ui
                     in components/ui
  client/            browser-only logic: db (IndexedDB Replica + Op Queue), replica,
                     sync, ops, actions, views, sort, dates, api, signin/relogin,
                     realtime (SSE), ui/ gestures, sw/service-worker.ts; store.ts
                     is a small subscribe/set store
  shared/            code for both sides: contract.ts (wire types + zod),
                     replica-contract.ts (frozen IndexedDB layout)
  server/            server-only, every file *.server.ts
    account/         /api/me, /api/onboard, per-user CalDAV engine
    auth/            identity: session (Better Auth), bearer tokens, CSRF
    caldav/          engine (DAV client), ics (VTODO mapping), recurrence
    crypto/          Fernet, byte-compatible with Python's cryptography
    db/              Drizzle schema, pool, migrations, Connected Accounts
    http/            error envelope, /api handler plumbing
    ops/  sync/      POST /api/ops, GET /api/sync, sync cursor
    realtime/        NOTIFY listener, SSE hub, notify helpers
  entrypoints/       bundled with `bun build --target bun` (migrate)
  start.ts           global request middleware (idle timeout, metrics, access
                     log, anti-framing headers, CSRF)
e2e/                 Playwright, against the built server (sw/: live service worker)
drizzle/             migrations; 0000_baseline.sql was pulled from Alembic's schema
```

### The UI is client-only, served as one shell

Every screen renders from the IndexedDB Replica, never from the server. The
SSR environment is built with `TSS_SHELL=true` (vite.config.ts), Start's SPA
flag: the server answers every page with the same shell (the root route and
AppGate's boot spinner), and the service worker precaches `/` and serves it
for every navigation, so a deep link cold-starts offline. Do not add loaders
or server rendering to the Replica screens; their data comes from
`src/client/`. The `/pending` and `/admin/*` pages are the exception: their
loaders call server functions, which run on the client after the shell loads.

Installed PWAs keep their Replica and queued ops across deploys, so treat
these as a contract: the IndexedDB name, version and stores
(`src/shared/replica-contract.ts`), the op wire format, the worker URL
`/service-worker.js` and the web manifest URL. Changing one needs a migration
path for data already on phones.

- The PWA is vite-plugin-pwa (injectManifest, `src/client/sw/`), run in the
  client build only: per-environment it would rewrite the worker after Nitro
  recorded its size, which truncates it when served.
- Gesture engines in `src/client/ui/` are DOM actions in the Svelte `use:`
  shape, attached with `useAction` (`src/components/useAction.ts`). A drop
  commits inside React's `flushSync`, so the reorder and the transform reset
  paint as one frame.
- An expired session is a 401 `unauthorized` envelope (`AuthWallError`); a
  401 `nextcloud_unauthorized` is the reconnect banner. Sign-in opens
  `/api/signin` in a popup; the fallback navigates to
  `/api/signin?return_to=<path>` after checking the server is reachable.
- A signed-in person who is not approved yet gets a 403 `access_pending`
  (`AccessPendingError`); AppGate sends the window to `/pending`. `/pending`
  and `/admin/*` render outside AppGate (`src/routes/__root.tsx`) and load
  through server functions, so they need no Connected Account. The service
  worker does not answer their navigations: the precached `/` shell
  hydrated on them is a React hydration mismatch (`e2e/sw/ungated.spec.ts`).
- `/api/events` (SSE): `poke` from another device, `resync`, and every
  (re)connect run the normal sync cycle. That is a delta sync from the
  stored cursor, not a full snapshot: the CalDAV sync-token delta is
  complete, so a lost poke delays a change but loses nothing.

## Commands

All commands use Bun 1.4.3 (`packageManager` in package.json). The devvm's
`~/.bun/bin/bun` may be older until the playbook installs 1.4.3; older Bun
cannot read this `bun.lock`.

```sh
bun install --frozen-lockfile
bun run check        # biome
bun run typecheck    # tsc --noEmit
bun run test         # bun test, src/ only
bun run build        # vite build + bundled entrypoints into .output/
bun run test:e2e     # Playwright against the built server (run build first)
bun run start        # serve .output on $HOST:$PORT
```

## Tests

- `bun test` with happy-dom and Testing Library. `bunfig.toml` sets
  `[test] root = "src"` and preloads `src/test/happydom.ts` (DOM globals,
  keeping Bun's fetch/Request/Response) and `src/test/setup.ts` (jest-dom
  matchers, cleanup, quiet logs). The test script sets `NODE_ENV=test`.
- Tests sit next to the code: `foo.server.ts` → `foo.server.test.ts`,
  `Thing.tsx` → `Thing.test.tsx`.
- Property tests use `fast-check`.
- Server functions need Start's request context, so test them over HTTP
  against the built server, not by importing them.
- Database tests run when `TEST_DATABASE_URL` is set (a role that can create
  databases); each test makes and drops its own database. See
  `src/server/db/db.server.test.ts` for a one-line Postgres container recipe.
- Fernet tokens recorded from Python's `cryptography`
  (`src/server/crypto/fixtures/fernet-python.json`) pin the stored format:
  existing `connected_accounts` rows were written that way.
- Two CalDAV test doubles, at different depths:
  - `src/server/caldav/testing/fake-nextcloud.server.ts` is a
    `CalDAVTransport`: the real engine and ICS mapper
    run against it. `fixtures.server.ts` beside it has the seeded user and
    the golden files.
  - `src/test/fake-nextcloud.server.ts` replaces the whole engine (FakeEngine,
    a simple line format, not ICS) for the ops and sync logic tests.
  - Route tests swap the engine with `setEngineFactoryForTests` or the
    transport with `setCalDAVTransportForTests`
    (`src/server/account/account.server.ts`). `src/test/postgres.server.ts`
    makes migrated throwaway databases.
- bun runs every test file in one process. A test that replaces a global
  (`fetch`, `indexedDB`, `EventSource`) restores it in `afterEach`;
  `bun:test` ignores a cleanup function returned from `beforeEach`.
- Playwright lives in `e2e/`, outside `bun test`'s root. For iOS Safari use
  `homelab ios`, not an emulated viewport. Projects: `mobile-chromium-touch`
  (`*-touch` specs, CDP touch), `desktop-chromium-mouse` (`*-mouse`, smoke),
  and `pwa` (`e2e/sw/`, a live service worker behind the per-test stub origin
  in `e2e/fixtures/pwa-server.ts`, with an OIDC stand-in). Gesture specs stub
  /api with `page.route`; a service worker's requests cannot be stubbed that
  way, hence the stub origin.

## Database

- Drizzle on Bun's SQL client (`drizzle-orm/bun-sql`). The pool holds at most
  4 connections and the realtime LISTEN connection is the fifth, which keeps a
  pod within ADR-0001's 5; the migrate entrypoint uses 1.
- `DATABASE_URL` has no password in production; the password is read from
  `DATABASE_PASSWORD_FILE` each time a connection opens, so Vault rotation
  does not break new connections.
- The schema matches the two tables the retired Python build created with
  Alembic exactly (`bun run db:generate` must say
  "No schema changes"). `enc_app_password` is a hand-written `bytea` custom
  type holding the Fernet token's ASCII bytes; `updated_at` uses `$onUpdate`.
- drizzle-kit ignores `alembic_version` (`tablesFilter`); the table stays in
  place, unmanaged.
- The baseline is recorded as applied, not run, on a database Alembic
  manages: `markBaselineIfLegacy` in `src/server/db/migrate.server.ts` inserts
  the baseline's hash and timestamp into `drizzle.__drizzle_migrations` when
  `public.alembic_version` exists and Drizzle has no rows yet. It runs under
  the same `pg_advisory_lock` as the migrator. A fresh database runs the
  baseline normally.

## Configuration

| Env | Meaning |
|---|---|
| `DATABASE_URL`, `DATABASE_PASSWORD_FILE` | Postgres; see above |
| `MIGRATIONS_DIR` | migrate entrypoint; `/app/drizzle` in the image |
| `TASKS_FERNET_KEY` | encrypts Nextcloud app passwords; existing rows need the same key |
| `TASKS_CALDAV_BASE_URL` | Nextcloud DAV root |
| `TASKS_LOCAL_TZ` | all-day recurrence zone, default `Europe/Sofia` |
| `PUBLIC_ORIGINS` | exact public origins: Better Auth's baseURL (the first) and trustedOrigins, and the CSRF allow-list |
| `OIDC_DISCOVERY_URL`, `OIDC_CLIENT_ID`, `OIDC_CLIENT_SECRET` | the Authentik provider; sign-in is off when any is unset |
| `BETTER_AUTH_SECRET` | signs session cookies and OAuth state (Vault KV via ESO) |
| `API_TOKEN_AUDIENCES` | client IDs accepted as `aud` on bearer JWTs; default `OIDC_CLIENT_ID` |
| `AUTHENTIK_API_URL` | Authentik base URL for membership checks and approvals |
| `AUTHENTIK_READER_TOKEN` | service account that may view users and groups |
| `AUTHENTIK_APPROVER_TOKEN` | token that may only add users to Tasks Users |
| `AUTHENTIK_USERS_GROUP_ID` | Tasks Users' UUID; looked up by name when unset |
| `TASKS_USERS_GROUP`, `TASKS_ADMINS_GROUP`, `TASKS_AGENTS_GROUP` | group names, default `Tasks Users`, `Tasks Admins`, `Tasks Agents` |
| `AUTHENTIK_GUEST_USERNAME` | the anonymous auto-login user, default `guest` |
| `DEV_USER` | dev and test identity (an admin member); ignored when `NODE_ENV=production` |
| `LOG_LEVEL` | `DEBUG`, `INFO` (default), `WARNING`, `ERROR` |
| `HOST`, `PORT` | listen address; the image uses `0.0.0.0:3000` |
| `METRICS_PORT` | second listener serving only `/metrics`; the image uses `9090`; unset means no metrics listener |

Every secret above also reads from a `*_FILE` path.

Logs are JSON lines on stderr with `ts`, `level`, `logger`, `msg` and extras.
Console output from Nitro, srvx and
uncaught errors goes through the same logger (logger `console`); srvx's
one-line shutdown notice is the only plain line. `/healthz` is on the app
port; `/metrics` (prom-client) is only on `METRICS_PORT`, which the ingress
never routes.

## Process lifecycle

`src/server/nitro-plugin.server.ts` runs once at boot
(`src/server/lifecycle.server.ts`):

- Bun closes a request that is idle for 10 s by default. `src/start.ts`
  raises it to 120 s per request (the engine allows 30 s per CalDAV call);
  `/api/events` lifts it entirely.
- The LISTEN connection opens at boot when `DATABASE_URL` is set, so the
  realtime gauges mean something before the first subscriber.
- SIGTERM/SIGINT close the SSE streams and the LISTEN connection, wait up to
  5 s for in-flight requests, close the pool and exit 0.

## Serving traffic

The app serves `tasks.viktorbarzin.me` from Deployment `tasks` (Service
`tasks`, ports 3000 and 9090) in infra `stacks/tasks`. What the ingress and
Deployment need, and why:

- Keep the default `rate-limit` middleware on the ingress. It runs the real-ip
  plugin, which sets `X-Real-Ip`; Better Auth's rate limiter keys on that
  header (`CLIENT_IP_HEADER` in `auth.server.ts`).
- Set `custom_content_security_policy = "frame-ancestors 'none'"` on the
  ingress. The default `csp-headers` middleware replaces the app's own CSP
  with one that lets any `*.viktorbarzin.me` page frame the app.
- Point `prometheus.io/port` at `9090` (`METRICS_PORT`).
- Provision `AUTHENTIK_READER_TOKEN` (view users and groups). Without it, or
  without `AUTHENTIK_API_URL`, every 15-minute membership re-check fails
  closed (not a member) and logs an ERROR. `AUTHENTIK_USERS_GROUP_ID` comes
  from Secret `tasks-authentik-approver`.
- Deploys: on master, `build.yml` pushes `ghcr.io/viktorbarzin/tasks:<sha>`,
  tags the next `vX.Y.Z` with svu, and triggers `.woodpecker/deploy.yml`,
  which sets that image on both containers of Deployment `tasks` (`migrate`,
  the init container, and `tasks`). Terraform ignores both images.

## Recurrence limits

Pinned by tests:

- `BYWEEKNO` rules are a per-op error on completion (ical.js lands one ISO
  week off).
- An RRULE ical.js cannot parse even upper-cased (e.g. `BYDAY=MO,0WE`) still
  shows the task as recurring in sync, but an edit to that task is a per-op
  error.

## Identity

`src/server/auth/` (ADR-0001, Identity and access):

- Browser sign-in is Better Auth's generic OAuth against Authentik, through
  `/api/auth/start?return=<path>` and `/api/auth/finish`. `/api/signin`
  (the popup target of tasks ADR-0004) starts it when there is no session.
  A guest from Authentik's public auto-login is sent back with `prompt=login`.
- Users are keyed on the OIDC `sub`. `identity_links` maps a subject to the
  `authentik_username` value the existing rows use, through
  `preferred_username`, once (`AuthUser.accountKey`).
- Membership in Tasks Users, Tasks Admins or Tasks Agents comes from the
  id_token's `groups` at sign-in and is re-asked from Authentik when older
  than 15 minutes (`member_checks`). A non-member gets 403 `access_pending`
  from `/api` and the `/pending` page; Tasks Admins approve at
  `/admin/requests`.
- Bearer JWTs (CLIs, agents) are verified in `tokens.server.ts`: RS256, the
  provider's issuer, `aud` in `API_TOKEN_AUDIENCES`, `exp`.
- The CSRF origin check in `src/start.ts` covers every state-changing request
  and `GET /api/events`.
- Tests use the mock Authentik in `src/server/auth/testing/`; the HTTP tests
  need a built server and `TEST_DATABASE_URL`.

## Realtime

`src/server/realtime/` (ADR-0001, Realtime contract): `publish(accountKey)`
(or `pokeUser`) sends `NOTIFY tasks_ops` with the account key and an event,
never task data. Each pod's listener holds one LISTEN connection, checks it
every 30 s with a ping NOTIFY that must come back on it, reconnects, and
sends `resync` to every stream after a reconnect. `GET /api/events` streams
`poke` and `resync` with a `: ping` comment every 25 s; the route lifts Bun's
10-second idle timeout for the stream.

## Image

`Dockerfile` builds on `oven/bun:1.4.3` and runs on
`oven/bun:1.4.3-distroless` as `USER 10001:10001`, copying only `.output` and
